## 1. Berkshire Hathaway 字幕研究的可复用结论

本次基于 `/mnt/d/downloads/BerkshireHathaway` 下 14 个 `.srt` 字幕文件，形成了新的经济理解框架，并归档到：

```text
refdocs/berkshire_hathaway_economic_knowledge_note_2026-06-05.md
```

最值得保留的知识点：

1. 利率是资产估值的重力。
   - 企业价值取决于未来现金流折现。
   - 利率上升会压低远期现金流现值、抬高融资成本、提高无风险替代收益。
   - 高估值、高久期、依赖融资扩张的资产受压更明显。

2. 现金不是收益资产，现金是选择权。
   - 现金的价值在于危机时的行动能力、等待能力和不被迫卖出的自由。

3. 通胀测试企业的真实质量。
   - 真正重要的是定价权、现金流质量、再投资回报和成本传导能力。

4. 保险浮存金的价值依赖承保纪律，而不是规模本身。
   - 便宜负债是资产，但错误定价的负债会变成风险。

5. 银行与信用周期的核心是信任。
   - 需要同时观察存款稳定性、资产质量、流动性、文化和激励机制。

6. 贸易总体有益，但分配冲击会制造政治反作用。
   - 这对全球化、关税、产业转移和资本账户理解都重要。

7. 中国和日本都提醒我们：不能把一个国家线性外推。
   - 中国要看产业链、政策、地产信用、地缘关系和资本配置。
   - 日本说明低利率、低增长、低通胀状态可以长期维持。

8. AI 要区分“技术强”与“可投资”。
   - 关键不是能力展示，而是谁能稳定捕获利润和定价权。

这些结论的一个直接产出，是进一步强化了本项目当前策略研发顺序：

```text
低频、低换手、质量、估值、现金流质量
    -> 过拟合与准入治理
    -> ML 二阶段 rerank
```

而不是优先追求复杂预测模型。

## 3. Tushare 财务回填与验收口径

本次会话重新梳理了 `market_financial_factors` 在 2016Q1-2018Q1 的覆盖情况，并形成可复用判断：

### 3.1 季度验收状态

可验收：

- `2016Q1` `2016-03-31`
- `2016Q2` `2016-06-30`
- `2016Q3` `2016-09-30`
- `2016Q4` `2016-12-31`
- `2017Q1` `2017-03-31`
- `2017Q2` `2017-06-30`
- `2017Q3` `2017-09-30`

需继续回填：

- `2017Q4` `2017-12-31`
- `2018Q1` `2018-03-31`

判断依据不是单一表行数，而是三层结合：

1. `market_financial_factors` 实际入库符号数
2. 关键字段覆盖率：`announce_date / roe / revenue_growth / profit_growth / cash_flow_quality / debt_to_asset`
3. `tushare_financial_backfill_tasks` 任务状态：`fetched / pending / failed / empty`

### 3.2 `empty` 的含义

`empty` 不是程序报错，也不等于失败。

它表示：

- 请求已经发出并返回
- 但返回结果为空，或者关键财务字段全为空
- 因而没有可写入的有效财务因子

这类情况通常意味着：

- 该股票该财报期确实没有可用财务数据
- 该期点未形成有效披露
- 接口返回壳行但没有指标值

### 3.3 当前卡住的根因

当前财务回填真正的瓶颈不是 token，也不是本项目命令写法，而是：

```text
cashflow 接口 code=40203
访问接口(cashflow)频率超限(20000次/天)
```

这条结论非常重要，因为它说明：

- `--max-requests-per-minute` 只能控制每分钟，不解决单日总额度
- 继续在同一天重跑 `--retry-failed`，只会把更多任务刷成 `failed`
- 当前阶段最有效的动作是隔日重跑，而不是继续提速

## 4. Tushare 2000 积分的真实含义

本次会话明确区分了“够不够权限”和“够不够工程效率”：

### 4.1 对 `income / balancesheet / cashflow / fina_indicator`

2000 积分：

- **够权限**：这四个接口都能使用
- **不够舒服**：不适合做全市场、多季度、逐股票的大规模历史财务回填

原因：

- 普通接口需要按 `ts_code + period` 逐条请求
- 历史回填量级大约是：

```text
9 个季度 * 5600 只股票 * 4 个接口 ≈ 201,600 次请求
```

- 实际运行中 `cashflow` 已经先撞到单日总额度

因此，2000 积分更适合：

- 日常增量更新
- 少量缺口补齐
- 单季度或少量股票补数

如果要高效做全市场历史财务补齐，5000 积分和 VIP 路径更合适。

## 5. Tushare 独立权限接口的项目优先级

本次会话基于官方权限说明，对“跟积分无关”的接口做了项目化筛选。

推荐优先级：

1. `research_report`
2. `anns_d`
3. `major_news`
4. `hk_daily + hk_adjfactor`
5. `npr`
6. `rt_k / rt_min_daily`

这里的核心逻辑是：

- 先补研究解释层和事件层
- 再补跨市场稳定数据层
- 最后才补盘中实时层

进一步压缩后的执行顺序：

### 第一梯队

- `research_report`
- `anns_d`
- `major_news`

理由：

- 最贴近 `T2.10 文本因子`
- 直接服务关注个股分析工具、日报解释、AI 摘要、单股评估报告
- 不需要先解决盘中交易系统问题

### 第二梯队

- `hk_daily`
- `hk_adjfactor`

理由：

- 用于提升港股映射层稳定性
- 主要改善跨市场 overlay 数据质量

### 观察梯队

- `npr`
- `rt_k / rt_min_daily`

理由：

- `npr` 适合做政策库，但短期 ROI 低于研报/公告/新闻
- `rt_k / rt_min_daily` 更适合未来 TUI/桌面实时工作台，不是当前主回测链路

## 7. `.env`、shell 环境与项目入口的区别

这次会话还澄清了一个容易混淆的点：

### `.env` 不等于 shell 环境变量

现象：

- `echo "$TUSHARE_TOKEN"` 可能为空
- 但项目 Python 入口里 `token_set` 仍然可以是 `True`

原因：

- 当前项目的 [phase0/config.py](../../phase0/config.py) 在 `load_config()` 时会先调 `load_project_env()`
- [phase0/env.py](../../phase0/env.py) 会把项目根目录 `.env` 里的变量加载进 Python 进程
- 所以项目 CLI/脚本可以看到 token，而普通 shell 里未必有 `export`

这条知识应长期保留，因为它能解释很多“shell 看不到变量，但项目能用”的现象。

## 8. 当前会话环境与宿主环境的差异

本次会话确认了一个环境层知识点：

- 宿主机普通 shell 里，`python3 -c "socket.getaddrinfo('api.tushare.pro', 80)"` 可正常解析
- 但当前受限 agent/sandbox 会话里的 Python `getaddrinfo` 可能失败
- 同时 `curl` 又可能正常

因此，不能把当前受限会话里的 DNS/网络行为直接等同于宿主机实际状态。

这条结论对今后判断“到底是数据源坏了，还是 agent 环境有限制”很重要。
