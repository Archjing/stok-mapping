# 中国 A 股股票量化交易策略研发报告

> 生成日期：2026-07-11  
> 调研问题：如何搭建一套面向中国 A 股的股票量化交易策略研发体系，避免回测幻觉，并形成可执行、可验证、可维护的研发流程？  
> 项目结论：A 股量化策略研发的核心不是“写一个策略并跑出漂亮收益曲线”，而是建立从交易规则、point-in-time 数据、策略假设、回测验证、成本成交、组合风控、模拟盘、实盘监控到治理归档的闭环。对 `stok-mapping` 当前阶段，推荐优先做中低频、可解释、低换手、成本敏感性可控的多因子/规则型选股与风控 overlay，暂不把高频、日内、复杂深度学习或全自动实盘交易作为主线。

## 1. 结论摘要

中国 A 股股票量化策略研发应按以下顺序推进：

1. 先定义交易问题：股票池、持有周期、调仓频率、收益目标、风险预算、是否允许空仓、是否允许融资融券、是否进入自动交易。
2. 先固化 A 股交易规则：T+1、涨跌幅、停复牌、ST/退市、新股前五日、100 股整手、0.01 元最小报价单位、交易时段、成本和程序化交易监管要求。
3. 先做数据治理，再做策略：原始数据保留、清洗数据可追溯、财报和成分股必须按 as-of 可见性约束，不能用未来公告、未来指数成分或事后复权信息污染回测。
4. 先有简单可解释 baseline，再引入复杂模型：多因子、低换手、低波动、价值/质量、残差动量/反转、事件和行业主题 overlay 都应先用简单版本证明边际贡献。
5. 先做 smoke test，再跑完整回测：数据链路、股票池、价格口径、成交假设和成本口径不过关时，任何收益指标都不可信。
6. 回测必须包含 walk-forward、连续 OOS、成本敏感性、参数稳定性、市场阶段分段和交易可执行性检查。
7. 模拟盘和小资金实盘的首要目标不是赚钱，而是校验“理论信号、理论成交、真实委托、真实成交、真实持仓、账户流水”之间的偏差。
8. 策略进入生产前必须有准入门槛、停用门槛、监控指标和复盘归档。没有门禁和撤退规则的策略，不应进入实盘辅助。

推荐路线：`数据可信 -> 因子可信 -> 组合可信 -> 回测可信 -> 模拟可信 -> 小资金可信 -> 扩大资金`。不要跳过中间层。

## 2. A 股市场约束如何进入研发

### 2.1 交易制度约束

| 约束 | 公开资料依据 | 研发影响 |
| --- | --- | --- |
| 交易时间 | 深交所交易规则：开盘集合竞价、连续竞价、收盘集合竞价有明确时段 | 回测必须明确是在开盘、盘中、收盘还是盘后生成信号；日线策略不能默认同日收盘信号同日收盘成交 |
| T+1 / 回转交易限制 | 深交所规则列明可当日回转的品种，普通 A 股不在清单内 | 股票策略买入后不能当天卖出；日内止损、T+0 反转、当日冲高回落捕捉等逻辑不能直接用于普通 A 股 |
| 100 股整手 | 深交所规则规定竞价买入证券的数量为 100 股或整数倍 | 组合权重必须转成整数股，资金利用率和小资金组合偏差要显式建模 |
| 最小报价单位 | 深交所规则规定 A 股申报价格最小变动单位为 0.01 元 | 回测中的委托价、涨跌停价和滑点后价格必须按 tick size 取整 |
| 涨跌幅限制 | 主板一般 10%，创业板/科创板一般 20%，北交所一般 30%；特殊情形另有规则 | 回测必须处理涨停买不进、跌停卖不出、无涨跌幅首日的极端波动 |
| 停复牌和新股首日/前五日 | 交易规则和数据接口均显示相关状态需要单独识别 | 股票池构建、成交假设、风险敞口和异常收益都要排除或标记 |
| 交易成本 | 交易所经手费、过户费、印花税、券商佣金、滑点和冲击成本叠加 | 高换手策略必须先在成本后过关；不能只用零成本结果立项 |
| 程序化交易监管 | 证监会和交易所要求程序化交易报告管理，高频有额外要求 | 只做研究回测不触发自动交易要求；一旦接券商自动下单，需把合规、报告、风控和应急方案纳入研发范围 |

### 2.2 对回测引擎的最低要求

A 股日线选股策略至少要在回测引擎中显式表达这些状态：

- `tradable`: 当日是否可交易，排除停牌、退市整理异常、数据缺失。
- `limit_up` / `limit_down`: 当日是否触及涨跌停；若用开盘或收盘成交，要模拟无法买入/卖出。
- `board_type`: 主板、科创板、创业板、北交所等，用于确定涨跌幅、申报数量和风险规则。
- `lot_size`: 默认 100 股，卖出零股需一次性处理。
- `price_tick`: A 股默认 0.01 元。
- `t_plus_1_lock`: 当日买入仓位次交易日才可卖出。
- `cash_available`: 下单前现金约束，不能回测中隐式透支。
- `cost_model`: 佣金、经手费、过户费、印花税、滑点、冲击成本。
- `signal_time` 和 `execution_time`: 例如 `T close signal -> T+1 open execution`，不能省略。

## 3. 数据体系

### 3.1 数据分层

推荐把数据分成 7 层：

| 层级 | 内容 | 验收重点 |
| --- | --- | --- |
| 原始层 `raw` | 数据源原样返回的行情、财务、公告、指数、成分股、交易日历 | 保留来源、抓取时间、请求参数、原始字段，不覆盖 |
| 标准化层 `normalized` | 统一代码、日期、字段类型、单位、币种、市场板块 | 可复现转换；字段口径有文档 |
| 质量标签层 `quality` | `validated/suspect/patched/excluded` | 异常不静默删除；修正有审计记录 |
| as-of 层 | 按当时可见性生成历史视图 | 财报公告日、指数成分生效日、行业分类变更日、ST/退市状态生效日必须可追溯 |
| 特征层 `features` | 因子、行业中性化结果、风险暴露、事件标签 | 每个特征有计算窗口、可见时间、依赖字段 |
| 研究面板层 `research panel` | 回测和因子分析用宽表/长表 | 固定 price mode、universe、rebalance calendar、缺失处理规则 |
| 实验结果层 `experiment` | 回测参数、指标、报告、日志、版本号 | 能从报告回到代码、数据版本和命令 |

### 3.2 必备字段清单

策略正式回测前，至少要具备：

- 证券主数据：代码、名称、上市日、退市日、市场板块、曾用名、ST/风险警示状态。
- 交易日历：交易日、是否开市、前后交易日映射。
- 日线行情：open/high/low/close/pre_close/volume/amount。
- 复权和公司行动：复权因子、分红、送转、配股、除权除息日。
- 停复牌和涨跌停：停牌状态、涨停价、跌停价、是否一字板。
- 股票池历史：指数成分、行业分类、项目自定义股票池，必须支持历史 as-of。
- 财务数据：利润表、资产负债表、现金流、财务指标、披露日期和报告期。
- 成本参数：佣金、税费、交易所费用、滑点和冲击成本。
- 基准数据：沪深 300、中证 500、中证 1000、全 A 或项目自定义基准。

### 3.3 Point-in-time 原则

凡是会在历史中变化的字段，都不能只保留“最新状态”。至少要记录：

```text
entity_id
field_name
value
effective_from
effective_to
announced_at
source
ingested_at
asof_time
quality_status
```

关键规则：

- 财务数据只能从公告日或可获得日之后进入信号，不能按报告期末直接可见。
- 指数成分不能用当前成分回测过去，必须用历史成分和权重。
- 行业分类、ST、退市状态、上市状态、名称变更都必须按历史版本。
- 复权价格要明确是前复权、后复权还是未复权；交易执行价格更适合使用真实未复权价格，收益评估可以使用复权收益序列。
- 对外部隔夜信号，例如美股、港股、商品、汇率，必须明确 A 股开盘前是否已经可见。

## 4. 策略研发地图

### 4.1 更适合当前阶段的策略类型

| 类型 | 适配度 | 理由 | 研发入口 |
| --- | --- | --- | --- |
| 低换手/低波/质量/价值多因子 | 高 | 中低频、可解释、可控成本，适合个人和本项目 Phase 0/1 | 因子 IC、分组收益、月度/周度调仓 |
| 残差动量/短期反转 | 高 | A 股存在强交易结构和散户行为特征，但需严控换手和成本 | 3-20 日信号衰减、成交可行性、行业/市值中性 |
| 行业/主题 overlay | 中高 | A 股政策和主题驱动明显，但主题数据容易后验污染 | 只做风险缩放或解释层，先不用作主 ranker |
| 事件驱动 | 中 | 财报、预告、公告、解禁、回购等可解释，但公告时点和可交易性要求高 | 事件窗口、公告后延迟、停牌处理 |
| 机器学习 rerank | 中 | 可以处理非线性，但易过拟合；应作为简单因子后的增强 | 固定特征、固定训练窗口、walk-forward、特征重要性 |
| 文本/LLM 情绪 | 中低 | 数据噪声、发布时间、语义误判和回测污染风险高 | 先做研究解释层和人工复核，不直接进主策略 |
| 高频/日内策略 | 低 | 数据、交易、延迟、合规和成本要求高，不适合当前主线 | 暂不进入主研发线 |
| 强化学习/深度模型直接交易 | 低 | 训练不稳定、样本外风险高、解释性差 | 仅保留为远期研究 |

### 4.2 因子六域框架

建议继续采用本项目已沉淀的六域框架：

```text
宏观制度 -> 行业主题 -> 公司价值 -> 风格风险 -> 资金交易 -> 信息事件
```

落地时不要一开始追求“大而全”。更稳健的优先级是：

1. 价格和成交：动量、反转、波动率、换手、流动性、成交额过滤。
2. 基础风险：市值、行业、Beta、残差波动、停牌/ST/新股过滤。
3. 财务质量：ROE、毛利率、现金流、杠杆、盈利稳定性，但必须受公告日约束。
4. 估值与分红：PE/PB/PS、股息率、估值分位，必须处理亏损和极端值。
5. 资金与事件：北向、龙虎榜、解禁、回购、业绩预告、公告事件。
6. 文本与主题：政策、新闻、研报、社交情绪，只做辅助解释或 overlay。

## 5. 标准研发流程

### Stage 0：立项

每个策略立项必须回答：

- 要解决什么问题：提高收益、降低回撤、降低换手、提高解释性，还是改善市场环境适配。
- 使用什么股票池：全 A、沪深 300、中证 500、中证 1000、行业池或自定义池。
- 使用什么价格：研究价格、交易执行价格、估值判断价格分别是什么。
- 信号何时生成，订单何时执行，执行时信息是否真实可见。
- 该策略为什么应该在 A 股有效，而不是从美股或加密市场直接迁移。
- 预期失败模式是什么：高波行情、风格切换、小盘流动性枯竭、政策冲击、单边下跌、涨跌停无法成交。
- 是否有一个简单 baseline 可作为对照。

输出物：一页策略任务单，不写代码也要能说清楚假设、数据、执行、风险和验收。

### Stage 1：数据准备与 smoke test

先跑数据体检，不跑收益：

- OHLC 是否满足 `low <= open/close <= high`。
- 成交量、成交额是否非负，停牌日是否错误出现成交。
- 涨跌幅是否超过交易所限制，超限是否可由复权、新股、北交所或无涨跌幅日解释。
- 股票池是否有历史版本，是否误用当前成分回填历史。
- 财报、公告、行业分类、ST 状态是否有可见时间。
- 基准指数是否完整，交易日是否对齐。
- 缺失、异常、补丁和排除样本是否输出报告。

输出物：数据质量报告。没有数据质量报告的回测只能作为临时探索。

### Stage 2：因子研究

先证明信号本身有信息，再谈组合收益：

- 横截面 Rank IC / Pearson IC。
- IC 均值、标准差、ICIR、正 IC 比例。
- 分组收益和多空收益。
- 因子衰减：1/3/5/10/20/60 日。
- 换手率和容量：因子排名变化、组合 turnover、成交额覆盖。
- 中性化前后对比：行业、市值、Beta。
- 极端值处理：winsorize、MAD、分位截尾，但要记录。
- 缺失值处理：缺失本身是否有信息，不能静默填未来值。

输出物：因子诊断报告。只有组合回测收益，没有因子诊断，不足以证明策略有效。

### Stage 3：组合构建

从简单组合开始：

- 选择方式：top N、分位数组合、阈值触发或得分加权。
- 权重方式：等权、风险缩放、行业中性、市值中性。
- 调仓频率：周、月优先；日频要先证明成本后仍有效。
- 约束：单票上限、行业上限、ST/停牌/新股过滤、最小成交额、最大换手。
- 现金：未成交资金留现金，不允许隐式满仓。
- 失败处理：涨停买不进、跌停卖不出、停牌无法调仓、零股卖出。

当前项目阶段推荐默认：

```text
日线信号 -> 次交易日执行
中低频调仓 -> 周度或月度优先
多头股票组合 -> 不做融券卖空
等权 baseline -> 再比较风险缩放或打分加权
沪深300/中证500/中证1000/全A等权 -> 至少一个基准
```

### Stage 4：回测验证

正式回测至少包括：

- 样本内/样本外分离。
- walk-forward 或滚动窗口。
- 连续 OOS 曲线，而不仅是 fold 均值。
- 和基准及当前已知 baseline 比较。
- 成本后主结果，不以零成本作为主结论。
- 成本敏感性：基础、主模拟、压力三档。
- 参数稳定性：参数邻域表现不能一变就崩。
- 市场阶段分段：牛市、熊市、震荡、高波、低波、大小盘风格切换。
- 子股票池分段：主板、创业板、科创板、北交所、大中小市值、行业。
- 换手、容量和无法成交统计。

主报告指标：

| 指标 | 用途 |
| --- | --- |
| 年化收益 | 收益水平，但不能单独使用 |
| Sharpe / Sortino | 风险调整收益 |
| 最大回撤 / Calmar | 下行风险和资金曲线承受度 |
| 胜率 / 盈亏比 | 交易分布特征 |
| 换手率 | 成本和容量核心指标 |
| 信息比率 | 相对基准稳定性 |
| OOS 衰减 | 过拟合风险 |
| 成本敏感性 | 实盘落差风险 |
| 暴露分解 | 行业、市值、风格来源 |
| 不可成交比例 | A 股可执行性 |

### Stage 5：过拟合控制

过拟合不是“模型太复杂”才出现，简单规则也会因为反复试参数而过拟合。必须记录：

- 一共试了多少策略、多少参数、多少过滤条件。
- 哪些失败结果被丢弃，不能只保留成功版本。
- 每次调参依据是什么，是经济解释、数据质量修复，还是纯收益追逐。
- 是否使用独立保留样本。
- 是否对多重检验做修正。
- 是否使用 PBO、Deflated Sharpe Ratio 或至少用参数邻域和 walk-forward 做简化替代。

项目内推荐的低成本替代做法：

1. 固定一份“不可反复查看”的保留样本。
2. 每个策略保存完整实验账本。
3. 参数只允许在小范围、可解释区域内搜索。
4. 报告必须列出失败版本和放弃原因。
5. 任何“收益突然大幅改善”的改动，都先按未来函数或数据污染排查。

### Stage 6：准入门槛

一个策略进入模拟或实盘辅助前，至少要满足：

- 数据 smoke test 通过。
- 策略 smoke test 通过，无未来函数和明显错误执行假设。
- 成本后收益为正，且不是单个窗口贡献。
- 最大回撤在资金承受范围内。
- 换手率和滑点敏感性可接受。
- 连续 OOS 不崩。
- 相对 baseline 有可解释增量。
- 失败模式、停用条件和复盘频率明确。
- 报告和命令可复现。

建议沿用本项目现有 gate 思路：

```text
annualized_return_mean > 0
sharpe_mean > 0.5
max_drawdown_mean > -0.25
win_rate_mean > 0.45
oos_return_decay_ratio < 0.30
```

这只是最低门槛，不是实盘许可。真正进入模拟或小资金前，还要通过成交偏差和账户级风控验证。

### Stage 7：模拟盘与小资金实盘

模拟盘要验证的是链路，不是收益承诺：

- 信号是否按预期生成。
- 委托是否按预期下达。
- 涨跌停、停牌、零股、现金不足是否正确处理。
- 理论成交和实际成交差多少。
- 真实账户持仓和系统持仓是否一致。
- 手续费、税费和滑点是否接近模型。
- 出错时是否能自动停机和人工接管。

小资金实盘首要目标：

1. 收集真实成交偏差。
2. 验证风控和停用规则。
3. 验证账户同步和异常恢复。
4. 验证人工干预是否破坏策略统计特征。

不要用 1-2 周小资金盈利直接推断策略有效。

## 6. 工程架构建议

推荐模块边界：

```text
data_ingestion
  -> raw storage
  -> normalization
  -> validation
  -> as-of view
  -> feature store
  -> strategy registry
  -> backtest engine
  -> experiment ledger
  -> report generator
  -> paper/simulation account
  -> live execution adapter
  -> monitoring and audit
```

关键工程要求：

- 策略注册表统一管理，不在回测主流程里散落临时代码。
- 每个策略实现统一接口：`prepare_panel / select_params / apply / metadata`。
- 回测配置必须可序列化，包含 universe、price mode、成本、调仓频率、参数、数据截止日。
- 每次实验有唯一 ID，绑定 git commit、数据版本、命令、输出文件。
- 报告生成自动化，不能只依赖控制台输出。
- 数据库和报告类本地资产要按项目规则管理，避免污染普通代码提交。
- 生产执行和研究回测隔离，避免研究脚本直接触达真实账户。

## 7. 安全、合规和运维风险

一旦从研究进入自动委托，风险等级明显提高：

- 程序化交易报告：按监管和券商要求履行报告或确认流程。
- 券商接口权限：密钥、交易密码、证书、token 不得写入代码或报告。
- 下单风控：最大单笔金额、最大日内成交额、最大撤单率、最大亏损、最大持仓偏离。
- 技术故障：行情断流、接口超时、重复下单、持仓不同步、成交回报延迟。
- 日志脱敏：账户、资金、持仓、委托流水不能随意进入公开报告或远端仓库。
- 供应链：数据源、依赖包、交易接口 SDK 要固定版本并做最小权限。
- 应急方案：自动停机、撤单、人工接管、回滚到只读模式。

本报告建议：当前阶段把 `stok-mapping` 继续定位为研究、模拟和辅助决策系统，不直接扩大到无人值守实盘自动交易。

## 8. `stok-mapping` 落地建议

### 8.1 当前应坚持的方向

结合项目已有文档，建议继续坚持：

- 中低频日线策略优先。
- A 股本土因子优先。
- 低换手、低波、质量、价格成交结构优先。
- 跨市场信号只做 overlay 或解释层，不能直接作为主 ranker。
- 复杂模型先做 rerank 或对照实验，不直接替代简单 baseline。
- 任何策略先过 smoke test，再进入 walk-forward / compare / gate。

### 8.2 建议补强的工程任务

| 优先级 | 任务 | 验收标准 |
| --- | --- | --- |
| P0 | 固化 A 股交易约束模型 | 回测引擎明确支持 T+1、涨跌停、停牌、100 股整手、tick size、现金约束 |
| P0 | 强化 as-of 数据视图 | 财报、指数成分、行业、ST、退市状态都有历史可见性字段 |
| P0 | 实验账本 | 每轮参数、命令、数据版本、失败实验、报告路径可查 |
| P1 | 因子诊断报告模板 | 每个因子输出 IC、分组收益、衰减、换手、暴露 |
| P1 | 成本和成交偏差模型 | 基础、主模拟、压力三档成本；统计不可成交和滑点敏感性 |
| P1 | 组合暴露报告 | 行业、市值、风格、单票集中度、换手、现金占比 |
| P2 | Paper account 对账 | 理论订单、模拟成交、账户持仓和账单一致 |
| P2 | 策略停用机制 | 连续 OOS 衰减、回撤、异常成交、数据质量失败可触发停用 |
| P3 | 文本/LLM 事件因子 | 先做解释层和候选提示，不作为主交易信号 |

### 8.3 90 天路线图

**0-30 天：可信回测底座**

- 固化交易规则和成本模型。
- 输出标准数据体检报告。
- 把现有 baseline 和候选策略统一跑一遍 smoke + walk-forward + gate。
- 建立实验账本，不再只保留成功结果。

**31-60 天：可信因子和组合**

- 建立因子诊断模板。
- 对低换手、低波、质量、价值、残差动量/反转做统一诊断。
- 对组合加入行业、市值、流动性和换手约束。
- 建立连续 OOS 和成本敏感性主报告。

**61-90 天：模拟与治理**

- 接入 paper account 的理论订单和模拟成交对账。
- 建立策略准入、降级、停用、复盘规则。
- 形成策略池视图：启用、观察、研究中、暂停、淘汰。
- 开始记录真实或模拟成交偏差，为小资金验证做准备。
