# stok-mapping 目标阶段路线图摘要

## 目标口径

`stok-mapping` 的终局不是 Phase 0 因子研究脚手架，而是一个完整的机器学习量化研究与应用平台。

---

## 新阶段定义

### Phase A：数据底座与治理
- Tushare 国内股票主源稳定化
- 明确 Tiingo / FRED 的计划主源角色与接入边界
- 明确 yfinance 仅作为 fallback 的职责边界
- 本地数据库治理
- source audit / freshness / PIT 规则
- 保留现有股票池与基础回测能力

### Phase B：特征与标签工厂
- 技术面、基本面、跨市场、文本特征生成
- 标签体系构建
- 统一训练/验证切分与 dataset builder

### Phase C：机器学习研究引擎
- sklearn 基线模型接入
- 滚动训练、滚动预测
- precision / recall / F1 / Sharpe / OOS 评估
- 预测与实验记录持久化

### Phase D：组合构建与风险控制
- 评分转权重
- 风险预算
- 行业/单票/流动性约束
- Markowitz / 协方差风险模型

### Phase E：账户级回测执行仿真
- 账户、持仓、交易、成本、调仓回放
- 净值、回撤、成交流水、重训练时点模拟

### Phase F：解释层与产品交付
- 盘前日报
- 观察池解释
- 风险场景分析
- Dashboard / PWA / Desktop
- LLM 解释辅助

---

## 与 Tushare 文档的映射

- `doc 90` → 数据接入 + 特征/标签 + 监督学习训练预测
- `doc 68` → 滚动评估 + 结果记录 + 组合分配
- `doc 63` → 账户/持仓/交易回放式回测引擎

---

## 实施优先级

### 最优先
1. 数据治理与 PIT 对齐
2. 特征与标签工厂
3. ML 基线研究引擎

### 次优先
4. 组合构建与风险约束
5. 账户级仿真

### 后续产品化
6. 应用界面与解释层
7. 更复杂深度学习模型

---

## 对当前项目的直接含义

- `phase0/` 应逐步从主架构退化为底座/legacy incubator
- `walk_forward.py` 不应继续无限扩展，而应拆成研究、组合、仿真等独立子系统
- 论文与研究报告应进入正式的研究证据链
- 开发计划需改写为“平台演进路线图”而非仅“Phase 0/1 研究任务表”
