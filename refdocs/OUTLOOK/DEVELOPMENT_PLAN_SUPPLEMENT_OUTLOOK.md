# DEVELOPMENT_PLAN 补充展望说明

> 目的：作为当前 `DEVELOPMENT_PLAN.md` 的**补充展望文件**存在。  
> 原则：**不替换、不覆盖、不轻易删除**旧版开发计划中已经形成的产品功能规划，只为后续整合新版平台化蓝图提供单独承载位置。

---

## 1. 文件定位

当前项目已经形成两种规划视角：

1. **旧版应用导向视角**  
   重点是尽快做出一个可应用的产品，包括：
   - A 股盘前研判
   - 观察池输出
   - 风险暴露说明
   - 信号等级
   - 本土主因子选股
   - 跨市场 overlay
   - 候选策略 compare / gate / report 链路
   - `07:30` 日报方向
   - 数据源升级到 Tushare / Tiingo / FRED 的落地路径

2. **新版平台化视角**  
   重点是从长远看，把项目逐步扩展为：
   - 特征工厂
   - 标签工厂
   - 机器学习研究引擎
   - 预测记录与滚动评估
   - 组合权重分配
   - 账户级回测仿真
   - 更完整的解释层与交付层

这两种视角不应相互替代，而应形成：

> **当前主计划 + 补充展望文件**

其中：
- `DEVELOPMENT_PLAN.md` 继续作为当前主线
- 本文件承载补充展望

---

## 2. 整合原则

后续整合必须遵守以下原则：

### 2.1 不轻易删除旧版已做好的功能规划

旧版计划书中已经明确的产品能力，应默认继续保留，包括：

- A 股盘前情景推演
- 观察池
- 风险暴露说明
- 信号等级体系
- 本土主因子排序
- 跨市场风险/情绪 overlay
- 候选 compare / gate / report 输出
- 报告化交付思路

### 2.2 新版蓝图只能作为补充展望逐步吸收

新版蓝图中提出的更重架构能力，不应直接推翻当前应用导向主线，而应作为：

- 中长期扩展方向
- 架构拆分储备
- ML 与回测仿真升级方向
- 后续模块化演进依据

### 2.3 平台化改造必须服务于产品可用性

任何新增层次、目录拆分或中后台重构，都应回答一个问题：

> 它是否有助于更快、更稳地形成一个可应用的产品？

如果答案是否定的，就不应优先实施。

---

## 3. 旧版主计划中必须继续保留的能力

以下能力应继续被视为本项目正式功能目标，而不是被新版蓝图弱化掉：

### 3.1 盘前研判产品能力
- 隔夜情绪解释
- 开盘情景推演
- 观察池输出
- 风险暴露说明
- 失效条件
- 报告化交付

### 3.2 本土主策略主线
- A 股本土主因子选股
- 候选策略比较
- effectiveness gate
- 持续优化 Sharpe 与回撤

### 3.3 应用导向的数据升级
- Tushare 作为国内股票主源
- Tiingo 作为美股/ETF 计划主源
- FRED 作为宏观/利率/VIX 计划主源
- yfinance 仅作为 fallback

### 3.4 快速形成可用产品
- 优先跑通可读、可比、可解释、可交付的链路
- 优先形成稳定产出的日报 / 观察池 / 报告
- 不为了“平台完整性”过早重写全部结构

## 4. 新版蓝图中可逐步吸收的部分

以下能力建议作为“补充展望”逐步进入项目：

### 4.1 近期可吸收
- sklearn 基线模型
- 简单监督学习排序/过滤
- 预测与实际结果记录
- 更系统的评估指标
- 更稳的风险约束/组合过滤

### 4.2 中期可吸收
- 特征工厂
- 标签工厂
- 滚动式模型评估
- 简化组合权重分配
- 账户级仿真雏形

### 4.3 长期保留为展望
- 更复杂深度学习模型
- 更重的平台化目录拆分
- 完整账户回放引擎
- 更成熟的 Dashboard / PWA / 桌面端统一产品层

---

## 5. 推荐整合顺序

后续如果要把新版蓝图并入主计划，建议顺序如下：

1. 先保留 `DEVELOPMENT_PLAN.md` 的旧版应用导向结构
2. 再用本文件单独承载新版补充展望
3. 以后每次只把“对当前产品最有帮助的一部分”吸收入主计划
4. 不一次性把主计划整体改写成纯平台化/学术化版本

也就是说，正确的路线是：

```text
旧版主计划（当前主线）
    +
补充展望文件（本文件）
    ↓
后续逐步整合
```

而不是：

```text
旧版主计划
    ↓
被新版平台化蓝图整体替换
```

## 7. 当前结论

当前最合理的规划组合是：

> **继续以旧版 `DEVELOPMENT_PLAN.md` 作为主计划推进产品开发；**  
> **将新版平台化蓝图放入本文件和 `TARGET_*` 文件中作为补充展望；**  
> **后续逐步整合，不轻易删除已经确认过的产品功能规划。**

这能同时满足：

- 你要的“快速达到可应用的产品”
- 以及未来仍可扩展到更完整 ML / 回测仿真 / 组合研究平台的长期方向
