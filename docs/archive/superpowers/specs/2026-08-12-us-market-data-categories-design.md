# 美国市场扩展数据类别：维护与研究读取设计

## 1. 目标与边界

本设计把已落库的 21 个美国市场标的组织为可维护的数据类别，并补齐标的级更新审计、数据质量审计、共同已完成交易日判定和统一研究读取接口。

第一阶段的目标是让数据能力可持续运行、可审计、可被研究模块安全使用；它**不改变** `cross_market_semiconductor_timing_etf_v1` 的下单条件、仓位、限价规则或模拟账户行为。现有正式信号仍仅为：同一已完成美国交易日的 `^SOX` 涨跌幅与 `^VIX` 收盘值。

不在本阶段实现的内容：

- 不把 AMD、TSM、FAANG、`^TNX`、BABA/JD/KWEB 自动变成交易过滤器。
- 不修改模拟账户已生成的订单、台账或账单。
- 不引入新的付费数据源或把本地 SQLite 数据库提交到 Git。
- 不改变日内 5 分钟 ETF 执行模块。

## 2. 现状和问题

当前 `phase0.data_governance.external_market_history` 已能按 `us_market_history.symbols` 增量更新日线，并写入：

- `us_daily_bars`：日线数据；
- `us_data_source_runs`：整次更新的汇总审计。

但 `symbols` 是无语义的扁平列表。新增标的即使已落库，也无法从配置和审计直接判断：它属于哪一类、服务哪个研究用途、是否是策略硬依赖、某个类别是否存在共同完成交易日、以及一次更新中哪个标的失败。

此外，当前策略与观察页分别直接读取 `us_daily_bars`。策略已经正确地用 SOX/VIX 的 SQL 内连接避免混合日期，但该规则未抽成可复用数据接口。

## 3. 采用方案

采用“配置目录 + 标的审计 + 研究读取器”的三层方案。

| 层 | 职责 | 主要产物 |
| --- | --- | --- |
| 数据目录 | 定义标的类别、用途、重要性与更新集合 | `us_market_history.instrument_groups` 配置与 SQLite 注册快照 |
| 更新与审计 | 每标的拉取、质量检查、新鲜度与类别可用性 | 标的级运行审计、类别健康摘要 |
| 研究读取 | 以 as-of 语义读取同一已完成美国交易日的数据与派生特征 | `us_market_features` 模块 |

这是最小可验证方案：保留现有数据表和命令入口，不引入第二套日线库；新类别先作为研究能力，通过留出期验证和 admission 后才可能接入交易逻辑。

## 4. 配置目录

`phase0.us_market_history` 保留现有全局运行项：`path`、`daily_table`、`provider`、`years`、新鲜度阈值等。

新增 `instrument_groups`，每组至少定义：

- `symbols`：组内标的，去重后构成更新任务的完整标的集合；
- `purpose`：供报告与网站展示的业务说明；
- `required_for`：声明依赖该组的策略或研究模块；
- `critical`：是否属于运行硬依赖；
- `asset_types`：股票、指数、ETF、利率、外汇等，供质量规则和展示使用。

第一版目录固定为以下组：

| 类别 | 标的 | 定位 | 是否当前策略硬依赖 |
| --- | --- | --- | --- |
| `core_signal` | `^SOX`, `^VIX` | 当前半导体 ETF 映射信号 | 是 |
| `semiconductor_breadth` | AMD、TSM、ASML、AMAT、LRCX、SMH | 半导体产业链共振和集中度研究 | 否 |
| `mega_tech_beta` | AAPL、MSFT、GOOGL、AMZN、META | 区分半导体需求与泛科技贝塔 | 否 |
| `rates` | `^TNX` | 利率环境过滤研究 | 否 |
| `china_tech_sentiment` | BABA、JD、KWEB | 中概与中国科技情绪研究 | 否 |
| `reference_and_fx` | `^NDX`, NVDA, `CNY=X` | 基准、龙头与汇率背景变量 | 否 |

为兼容现有配置，运行时从目录扁平化出标的列表；若暂时没有 `instrument_groups`，继续读取旧 `symbols`。因此这是向后兼容迁移，旧配置不会立刻失效。

## 5. 更新、审计与质量规则

### 5.1 标的级审计

新增表 `us_data_source_symbol_runs`。每个标的每次更新写一条记录，至少包括：

- 父级 `us_data_source_runs.id`；
- 类别名、标的、资产类型；
- 请求开始日、请求结束日、来源；
- 拉取、插入、更新行数；
- 更新后的该标的最新日期；
- `updated`、`empty`、`failed`、`invalid_data` 等状态；
- 错误或质量问题摘要。

全局 `us_data_source_runs` 保持为一次命令的汇总结果，作为编排器现有健康检查的兼容接口。更新结果中任何硬依赖标的失败、缺失或质量异常时，汇总状态必须不可被标记为成功。

### 5.2 数据质量

数据入库前执行日线基础规则：

- `date`、`open`、`high`、`low`、`close` 必须存在；
- OHLC 必须为正数；
- `low ≤ open/close ≤ high`；
- 同一标的同一日期不得重复。

`volume=0` 不作为失败条件，因为指数、汇率和利率序列可合法无成交量。质量失败的行不得覆盖既有有效行；标的审计写为 `invalid_data`，汇总审计保留具体警告。

例行更新保持现有“最近日期向前重叠 7 天”的纠正窗口。首次新增标的仍使用完整配置历史；失败不静默降级为 `up_to_date`。

### 5.3 新鲜度与共同交易日

新鲜度按标的检查，基于该资产应有的最近已完成美国交易日与允许滞后天数。类别健康摘要还必须计算组内所有标的的最近共同日期。

任何多标的特征或策略信号只允许使用同一个共同完成交易日：

- `core_signal` 的 SOX 与 VIX 必须同日；
- 研究组可在共同日期上计算横截面对比；
- 若没有共同日期，读取器返回明确的不可用状态，禁止前向填充把不同日期拼为一个信号。

## 6. 统一研究读取接口

新增独立模块 `phase0.data_governance.us_market_features`，负责读取而不负责交易决策。接口以 `as_of_date` 和类别/标的请求为输入，返回带元数据的不可变结果：

- 已使用的共同完成美国交易日；
- 每个标的的最新可用日期、新鲜度、来源与质量状态；
- 指定窗口的收盘价、收益率、滚动波动和相对强弱等基础研究字段；
- 缺失、不同步或陈旧时的状态和可读原因。

第一版提供两类读取：

1. `load_completed_market_snapshot(...)`：一个共同交易日的收盘行情与质量元数据；
2. `load_group_daily_features(...)`：一段共同交易日面板，计算原始收益和基础滚动特征。

读取器不输出买卖信号，不改变仓位，也不自动应用任何过滤器。策略若读取它，必须在自身配置中显式声明依赖的组。

## 7. 消费者改造

### 7.1 当前策略

`CrossMarketSemiconductorTimingStrategy` 改为通过读取器取得 `core_signal`，但输入和结果保持不变：SOX 收益率、VIX 收盘值以及映射到下一中国交易日的规则完全保留。迁移的目的是统一 as-of 和共同日期保障，而不是改变策略。

### 7.2 盘前观察页

“半导体ETF美股情绪映射择时_v1”的观察页继续突出 SOX/VIX 信号，并新增“研究市场背景”区域：

- 只展示各研究类别的最近共同完成日、标的收盘与单日涨跌；
- 显示数据状态和来源；
- 明确标注“仅供研究观察，不参与当前自动交易信号”。

现有美股新闻区保持人工研判定位，不转换为自动信号。

### 7.3 命令、编排与健康检查

保持 `update-us-market-history` 命令和 `us_market_history` 编排任务不变。命令输出扩展为：类别覆盖、失败标的和最近共同日期摘要。`--check-only` 执行同样的目录、质量与共同日期检查，但不写数据。

数据库健康报告复用标的级审计，能回答“哪个标的/类别为何失败”。计划任务仍在美国市场完成日线后运行；中国盘前策略读取已完成美国交易日，不等待不存在的同日完整 OHLC。

## 8. 失败处理与降级

| 情况 | 系统行为 |
| --- | --- |
| 非关键研究标的抓取失败 | 标的审计记录失败，汇总任务呈警告或部分失败；现有 SOX/VIX 策略不改变下单规则 |
| `^SOX` 或 `^VIX` 抓取失败且无新鲜共同日 | 核心组健康失败；盘前观察页显示不可用原因；策略不产生基于混合日期的新信号 |
| 返回无效 OHLC | 不覆盖历史有效数据，记录 `invalid_data` |
| 某组缺少共同日期 | 该组特征不可用；不前填，不与其他日期拼接 |
| 配置类别遗漏或标的重复 | 启动配置校验报错；不执行不确定的更新 |

## 9. 测试与验收

单元测试：

- 从类别目录正确得到去重更新标的，并兼容旧 `symbols`；
- 每标的成功、空数据、抓取异常和无效 OHLC 均写入正确审计状态；
- 无效行不覆盖既有有效日线；
- 共同交易日计算不混用日期；
- `volume=0` 的指数、外汇和利率行可通过质量检查。

集成测试：

- `update-us-market-history --check-only` 输出类别、标的和共同日期健康摘要；
- 21 标的的类别覆盖及标的级审计可从 SQLite 查询；
- 观察页读取器显示 SOX/VIX 和研究背景，但明确不改变信号；
- 当前策略在既有固定输入上的信号、交易日期和结果与改造前一致。

验收标准：

1. 新增类别在配置中有明确用途、标的和关键性，更新任务实际维护它们；
2. 任一标的失败都能在 SQLite 审计与命令输出中定位；
3. 全部类别可报告共同完成交易日，核心组绝不混用 SOX/VIX 不同日期；
4. 新增数据可由研究读取器复用，当前策略交易条件和回测基线不变；
5. 数据库、日志、报告和临时产物不纳入 Git 提交。

## 10. 实施顺序与风险控制

1. 先实现配置目录与向后兼容解析，并用纯配置测试锁定 21 标的集合。
2. 迁移 SQLite 表并写入标的级审计、入库质量门。
3. 实现共同日期和研究读取器，迁移策略读取路径后做回归对比。
4. 扩展 CLI 健康摘要与观察页的研究背景展示。
5. 在独立研究工作树中评估候选过滤器；只有通过留出期与 admission，才另行提出交易规则变更。

风险最高的是“数据能力扩展后意外改变交易信号”。因此实施中对策略设置固定样本回归测试，且研究类别默认 `critical: false`、不会进入下单逻辑。第二个风险是外部源限流；标的级审计和失败状态将把问题显式暴露给编排器和网站，而不是掩盖为全库新鲜。
